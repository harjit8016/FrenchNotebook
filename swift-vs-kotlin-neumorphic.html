iOS to KMP / CMP

Swift concurrency vs Kotlin coroutines

The 5 patterns that come up first when moving from iOS to Kotlin Multiplatform.

iOS / Swift
KMP / Kotlin

Async / await

Non-blocking calls

Both wrap suspending work in a structured block. Kotlin needs an explicit scope; Swift's Task owns its lifecycle.

Task { let data = await fetchData() print(data) }
scope.launch { val data = fetchData() // suspend println(data) }

Actor model / mutex

Protecting shared state

Swift actors serialize access automatically. Kotlin has no actor type — you reach for a Mutex instead.

actor StateActor { private var count = 0 func inc() { count += 1 } }
class StateClass { private val lock = Mutex() private var count = 0 suspend fun inc() = lock.withLock { count++ } }

Main thread

UI updates

Same idea, both sides: pin work to the main thread before touching UI. @MainActor vs Dispatchers.Main.

@MainActor func updateUI() { tableView.reloadData() }
scope.launch(Dispatchers.Main) { // Update Compose UI }

Background threads

Worker / CPU work

Kotlin splits work by intent: Default for CPU-bound, IO for blocking network/disk. Swift's global queue doesn't distinguish.

DispatchQueue.global().async { // Heavy CPU work }
scope.launch(Dispatchers.Default) { // Heavy CPU work } // Use Dispatchers.IO instead // for network / disk calls

Detached tasks

Unstructured concurrency

Both start work outliving the current scope. Swift has a built-in API; Kotlin needs a new CoroutineScope by hand.

Task.detached( priority: .background ) { // Not tied to parent scope await doHeavyWork() }
val customScope = CoroutineScope(SupervisorJob()) customScope.launch( Dispatchers.Default ) { // Not tied to current scope doHeavyWork() }
